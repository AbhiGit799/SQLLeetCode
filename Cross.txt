
📖 Definition
===============
A CROSS JOIN in SQL combines every row from one table with every row from another table.
It’s also called a Cartesian join because the result is the Cartesian product of the two sets.

Query
======
SELECT s.student_name, sub.subject_name
FROM Students s
CROSS JOIN Subjects sub;

🧩 Example
Imagine two tables:

Students
=========
| student_id | student_name |
| ---------- | ------------ |
| 1          | Alice        |
| 2          | Bob          |

Subjects
========
| subject_name |
| ------------ |
| Math         |
| Physics      |


Output
=======
| student_name | subject_name |
| ------------ |------------- |
| Alice        | Math         |
| Alice        | Physics      |
| Bob          | Math         |
| Bob          | Physics      |


👉 Notice how every student is paired with every subject.

🚀 Key Points
===============
No condition is needed in a CROSS JOIN.
Result size = (rows in Table A) × (rows in Table B).
Useful when you need all possible combinations (like student–subject pairs in LeetCode 1280).
Often combined with LEFT JOIN and GROUP BY to count or filter results.

🎯 Analogy
============
Think of it like making outfits:
Table A = Shirts (Alice, Bob)
Table B = Pants (Math, Physics)
CROSS JOIN = Every shirt goes with every pant → all possible outfits.


🏦 Real‑World Scenarios
========================
Banking Reports  
================
Suppose a bank wants to track how many times each customer has interacted with each type of service 
(Loans, Credit Cards, Savings).

Customers table → list of all customers.

Services table → list of all services.

CROSS JOIN → generates all possible customer–service pairs.

Then, a LEFT JOIN with transactions shows how many times each customer used each service.
👉 This ensures even unused services show up with a count of 0.


Education Analytics  
In universities, administrators want to know how many exams each student attended for each subject.

Students × Subjects → CROSS JOIN.

Join with Exam records → count attendance.
👉 This is exactly the LeetCode 1280 Students and Examinations problem.


Sales Dashboards  
Retail companies often need to see sales per product per region.

Products table × Regions table → CROSS JOIN.

Join with Sales data → count or sum sales.
👉 Helps identify gaps (e.g., products not sold in certain regions).




🎯 Why It’s Useful
====================
Guarantees completeness: no missing combinations.
Works as a baseline grid for reporting.
Often paired with LEFT JOIN + COUNT/SUM to fill in zeros where activity didn’t happen.

Think of CROSS JOIN as a framework builder: it lays out every possible combination, 
and then you overlay real data to see what’s happening versus what’s missing.

ON Clause is not required in CROSS join?
Exactly, Arjun — that’s one of the defining traits of a CROSS JOIN.

🔑 Why ON Clause Isn’t Required
In a CROSS JOIN, SQL doesn’t need a condition because the intent is to produce all possible combinations of 
rows from both tables.

The result is the Cartesian product:

Rows in Table A
×
Rows in Table B
That’s different from INNER JOIN or LEFT JOIN, where you must specify an ON clause to tell SQL how to match rows.

👉 No ON clause needed — SQL automatically pairs every row from Students with every row from Subjects.

🎯 Key Takeaway
================
CROSS JOIN → no ON clause required.
INNER/LEFT/RIGHT JOIN → ON clause required to define matching logic.
Use CROSS JOIN when you want all combinations, not just matched pairs.
