/*
601. Human Traffic of Stadium

Table: Stadium

+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| visit_date    | date    |
| people        | int     |
+---------------+---------+
visit_date is the column with unique values for this table.
Each row of this table contains the visit date and visit id to the stadium with the number of people during the visit.
As the id increases, the date increases as well.
 

Write a solution to display the records with three or more rows with consecutive id's, and the number of people is greater than or equal to 100 for each.

Return the result table ordered by visit_date in ascending order.

The result format is in the following example.

 

Example 1:

Input: 
Stadium table:
+------+------------+-----------+
| id   | visit_date | people    |
+------+------------+-----------+
| 1    | 2017-01-01 | 10        |
| 2    | 2017-01-02 | 109       |
| 3    | 2017-01-03 | 150       |
| 4    | 2017-01-04 | 99        |
| 5    | 2017-01-05 | 145       |
| 6    | 2017-01-06 | 1455      |
| 7    | 2017-01-07 | 199       |
| 8    | 2017-01-09 | 188       |
+------+------------+-----------+
Output: 
+------+------------+-----------+
| id   | visit_date | people    |
+------+------------+-----------+
| 5    | 2017-01-05 | 145       |
| 6    | 2017-01-06 | 1455      |
| 7    | 2017-01-07 | 199       |
| 8    | 2017-01-09 | 188       |
+------+------------+-----------+
Explanation: 
The four rows with ids 5, 6, 7, and 8 have consecutive ids and each of them has >= 100 people attended. Note that row 8 was included even though the visit_date was not the next day after row 7.
The rows with ids 2 and 3 are not included because we need at least three consecutive ids.



*/



/* Write your PL/SQL query statement below */

WITH ValidGroups AS (
    SELECT s1.id AS start_id
    FROM Stadium s1
    JOIN Stadium s2
        ON s2.id = s1.id + 1
    JOIN Stadium s3
        ON s3.id = s1.id + 2
    WHERE s1.people >= 100
      AND s2.people >= 100
      AND s3.people >= 100
)
SELECT DISTINCT s.id, TO_CHAR(s.visit_date, 'YYYY-MM-DD') AS visit_date, s.people 
FROM Stadium s 
JOIN ValidGroups g ON s.id BETWEEN g.start_id AND g.start_id + 2 
ORDER BY visit_date;


/*

What are s1, s2, and s3?
***************************
They are table aliases. We are using the same Stadium table three times, 
and each alias gives one use of that table a different name.

FROM Stadium s1
JOIN Stadium s2
    ON s2.id = s1.id + 1
JOIN Stadium s3
    ON s3.id = s1.id + 2

Think of it like this:
- s1 = first record in the sequence
- s2 = second record in the sequence
- s3 = third record in the sequence

All three aliases refer to the same original Stadium table. They are not three separate tables.



What approach did we use?
***************************
We used the self-join approach.
A self-join means joining a table with itself to compare different rows from that same table.
Our thinking process is:
1. Find three consecutive IDs.
2. Check whether all three records have people >= 100.
3. Record the starting ID of every qualifying group.
4. Return all records that belong to those groups.
5. Use DISTINCT to avoid duplicate records when groups overlap.
For example, if IDs 2, 3, 4, and 5 all have at least 100 people, we find two qualifying groups:
- Group 1: IDs 2, 3, 4
- Group 2: IDs 3, 4, 5
Because IDs 3 and 4 appear in both groups, we use DISTINCT to return each record only once.


*/


/*

Let's understand this line step by step. It is the part of the query that returns all records 
belonging to a valid group of three consecutive IDs.

JOIN ValidGroups g
    ON s.id BETWEEN g.start_id AND g.start_id + 2

1. What does ValidGroups g mean?
In our previous query, we created a CTE (a temporary named result) called ValidGroups:

WITH ValidGroups AS (
    SELECT s1.id AS start_id
    FROM Stadium s1
    JOIN Stadium s2
        ON s2.id = s1.id + 1
    JOIN Stadium s3
        ON s3.id = s1.id + 2
    WHERE s1.people >= 100
      AND s2.people >= 100
      AND s3.people >= 100
)

Suppose IDs 2, 3, 4, and 5 all have at least 100 people.
The ValidGroups result would look like this:

start_id
2
3

Why? Because:
- Starting at ID 2 gives us the group 2, 3, 4.
- Starting at ID 3 gives us the group 3, 4, 5.
Here, g is simply an alias for ValidGroups, just as s is an alias for Stadium.


2. What does BETWEEN mean?
The condition:

s.id BETWEEN g.start_id AND g.start_id + 2

means:

s.id >= g.start_id
AND s.id <= g.start_id + 2

BETWEEN includes both endpoints.
For example, if g.start_id = 2, the condition becomes:

s.id BETWEEN 2 AND 4

So it matches IDs 2, 3, and 4.
