/*
Table: RequestAccepted

+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| requester_id   | int     |
| accepter_id    | int     |
| accept_date    | date    |
+----------------+---------+
(requester_id, accepter_id) is the primary key (combination of columns with unique values) for this table.
This table contains the ID of the user who sent the request, the ID of the user who received the request, and the date when the request was accepted.
 

Write a solution to find the people who have the most friends and the most friends number.

The test cases are generated so that only one person has the most friends.

The result format is in the following example.

 

Example 1:

Input: 
RequestAccepted table:
+--------------+-------------+-------------+
| requester_id | accepter_id | accept_date |
+--------------+-------------+-------------+
| 1            | 2           | 2016/06/03  |
| 1            | 3           | 2016/06/08  |
| 2            | 3           | 2016/06/08  |
| 3            | 4           | 2016/06/09  |
+--------------+-------------+-------------+
Output: 
+----+-----+
| id | num |
+----+-----+
| 3  | 3   |
+----+-----+
Explanation: 
The person with id 3 is a friend of people 1, 2, and 4, so he has three friends in total, which is the most number than any others.
 

Follow up: In the real world, multiple people could have the same most number of friends. Could you find all these people in this case?
*/



Solution => 

SELECT id, num
FROM (
    SELECT id, COUNT(*) AS num
    FROM (
        SELECT requester_id AS id
        FROM RequestAccepted
        UNION ALL
        SELECT accepter_id AS id
        FROM RequestAccepted
    ) all_friends
    GROUP BY id
    ORDER BY num DESC
)
WHERE ROWNUM = 1;


=========================================================================================================================================

⚖️ Why this works
====================
Symmetry: Both requester and accepter contribute equally to friendships.
Efficiency: Aggregation (GROUP BY) ensures counts are computed in one pass.
Oracle-specific handling: Since Oracle doesn’t support LIMIT, we use ROWNUM or FETCH FIRST.

The approach I used here is a normalization + aggregation strategy:

1) Normalize friendships
Friendships are stored asymmetrically: one row has a requester_id and an accepter_id.
To treat both sides equally, I flattened them into a single column (id) using UNION ALL.
This way, every person appears once for each friendship they are part of.

2) Aggregate counts
After normalization, I grouped by id and counted occurrences.
Each occurrence represents one friend connection, so the count gives the total number of friends per person.

3) Find the maximum
Since the problem guarantees only one person has the most friends, I simply ordered by the count (num) in descending order.
In Oracle, instead of LIMIT, I used either:
ROWNUM = 1 (classic Oracle), or
FETCH FIRST 1 ROWS ONLY (Oracle 12c+).


4) Return result
The outer query selects the top row, giving the person’s id and their friend count num.


Imp Note
=========
The normalization I used in Normalize friendships is a form of structural normalization of asymmetric 
relationships into a symmetric representation. Let me break it down:

🔍 What kind of normalization?
===============================
Union-based normalization
The original table has two separate columns: requester_id and accepter_id.
Each row represents a directed action (one person requests, another accepts).
But for counting friendships, both sides should be treated equally.
